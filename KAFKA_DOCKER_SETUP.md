# Kafka Docker Setup & Runtime Configuration

This document explains how to properly configure and run the Kafka container with secure JMX monitoring.

## Overview

The Kafka Dockerfile (`Dockerfile.kafka`) is designed to support multiple deployment scenarios with flexible, runtime-driven configuration. It does **not** bake in environment-specific values, allowing the same image to run in Docker Compose, Kubernetes, and cloud environments (Render, etc.).

## Required Environment Variables

### KAFKA_ADVERTISED_LISTENERS (REQUIRED)

This variable **must** be set at container runtime and defines how clients connect to your Kafka broker.

**Why it's not in the Dockerfile**: The advertised listeners depend on your deployment topology:
- **Docker Compose (local)**: `PLAINTEXT://kafka:29092,PLAINTEXT_HOST://localhost:9092`
- **Kubernetes (internal)**: `PLAINTEXT://kafka-broker.default.svc.cluster.local:9092`
- **Render.com**: `PLAINTEXT://kafka-service:9092` or the public hostname
- **Multi-datacenter**: Different hostnames/IPs for each listener

#### Example Usage

**Docker Compose**:
```bash
docker-compose run --rm kafka \
  -e KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://kafka:29092,PLAINTEXT_HOST://localhost:9092
```

**Docker run**:
```bash
docker run -e KAFKA_ADVERTISED_LISTENERS=PLAINTEXT://kafka:9092 <image>
```

**Kubernetes (with secrets)**:
```yaml
apiVersion: v1
kind: Pod
metadata:
  name: kafka
spec:
  containers:
  - name: kafka
    image: my-kafka:latest
    env:
    - name: KAFKA_ADVERTISED_LISTENERS
      value: "PLAINTEXT://kafka-broker.default.svc.cluster.local:9092"
    - name: KAFKA_BROKER_ID
      value: "1"
```

## Secure JMX Mode (Production)

When `JMX_SECURE=true` (the default), the container requires three additional configurations:

### 1. Secret Files (Required)

Mount or provide these files at `/etc/secrets/` with restricted permissions (readable only by Kafka process):

- **`/etc/secrets/jmxremote.password`** – JMX authentication credentials
  ```
  username password
  ```
  Must have permissions `600` and ownership restricted to Kafka user.

- **`/etc/secrets/jmxremote.access`** – JMX access control rules
  ```
  username readwrite \
    create javax.management.Attribute,\
    create javax.management.openmbean.CompositeData,\
    create javax.management.openmbean.TabularData,\
    invoke,\
    getAttribute,\
    setAttribute,\
    getMBeanInfo,\
    getClassLoaderFor,\
    getClassLoader,\
    getObjectInstance,\
    instanceof,\
    queryMBeans,\
    queryNames
  ```
  Must have permissions `600`.

- **`/etc/secrets/kafka.server.keystore.jks`** – Server keystore (generated by `secrets/generate-keystores.sh`)
- **`/etc/secrets/kafka.server.truststore.jks`** – Server truststore (generated by `secrets/generate-keystores.sh`)

### 2. Environment Variables (Required for Secure Mode)

- **`KEYSTORE_PASSWORD`** – Password for `kafka.server.keystore.jks`
- **`TRUSTSTORE_PASSWORD`** – Password for `kafka.server.truststore.jks`

These **must** be provided at runtime; there are no defaults in the Dockerfile.

#### Generating Keystores

Use the provided script to generate keystores and truststores:

```bash
./secrets/generate-keystores.sh
```

This script will:
1. Generate cryptographically strong random passwords if not already set
2. Create self-signed certificates
3. Generate JKS keystores and truststores
4. Set proper file permissions (600)

**Store the generated passwords securely** (e.g., in a secrets manager, environment file with restricted access, or Docker secrets).

### 3. Container Startup

When starting with secure JMX, provide all required passwords and mount the secrets directory:

**Docker run**:
```bash
docker run \
  -v /path/to/secrets:/etc/secrets:ro \
  -e KEYSTORE_PASSWORD="your-keystore-password" \
  -e TRUSTSTORE_PASSWORD="your-truststore-password" \
  -e KAFKA_ADVERTISED_LISTENERS="PLAINTEXT://kafka:9092" \
  -e JMX_SECURE=true \
  my-kafka:latest
```

**Docker Compose**:
```yaml
services:
  kafka:
    image: my-kafka:latest
    environment:
      KAFKA_ADVERTISED_LISTENERS: "PLAINTEXT://kafka:29092,PLAINTEXT_HOST://localhost:9092"
      KEYSTORE_PASSWORD: ${KEYSTORE_PASSWORD}
      TRUSTSTORE_PASSWORD: ${TRUSTSTORE_PASSWORD}
      JMX_SECURE: "true"
    volumes:
      - ./secrets:/etc/secrets:ro
    ports:
      - "9092:9092"
      - "9999:9999"
```

**Kubernetes (with Docker secrets)**:
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: kafka-jmx-secrets
type: Opaque
stringData:
  KEYSTORE_PASSWORD: "your-password"
  TRUSTSTORE_PASSWORD: "your-password"
---
apiVersion: v1
kind: Pod
metadata:
  name: kafka
spec:
  containers:
  - name: kafka
    image: my-kafka:latest
    env:
    - name: KAFKA_ADVERTISED_LISTENERS
      value: "PLAINTEXT://kafka:9092"
    - name: JMX_SECURE
      value: "true"
    - name: KEYSTORE_PASSWORD
      valueFrom:
        secretKeyRef:
          name: kafka-jmx-secrets
          key: KEYSTORE_PASSWORD
    - name: TRUSTSTORE_PASSWORD
      valueFrom:
        secretKeyRef:
          name: kafka-jmx-secrets
          key: TRUSTSTORE_PASSWORD
    volumeMounts:
    - name: jmx-secrets
      mountPath: /etc/secrets
      readOnly: true
  volumes:
  - name: jmx-secrets
    secret:
      secretName: kafka-jmx-secrets
      defaultMode: 0600
```

## Development Mode (JMX_SECURE=false)

⚠️ **Only for isolated development/test environments** – Never use in production.

To disable JMX authentication and SSL, build or run with `JMX_SECURE=false`:

```bash
docker run \
  -e JMX_SECURE=false \
  -e KAFKA_ADVERTISED_LISTENERS="PLAINTEXT://localhost:9092" \
  my-kafka:latest
```

In development mode:
- JMX authentication is disabled
- JMX SSL is disabled
- All security-related environment variables are optional
- Direct JMX access is allowed from any client on port 9999

## Health Checks

The container includes a built-in health check that validates the Kafka broker is responding:

```
HEALTHCHECK --interval=30s --timeout=10s --start-period=15s --retries=3 \
  CMD kafka-broker-api-versions --bootstrap-server localhost:9092
```

This will fail and mark the container as unhealthy if:
- The broker is not responding
- Port 9092 is unreachable

## Troubleshooting

### Container exits with "ERROR: JMX password file not found"

**Cause**: In secure mode, the container cannot find `/etc/secrets/jmxremote.password`

**Fix**:
1. Generate secrets: `./secrets/generate-keystores.sh`
2. Mount the secrets directory: `-v ./secrets:/etc/secrets:ro`
3. Verify file permissions: `ls -la secrets/jmxremote.*`

### Container exits with "KEYSTORE_PASSWORD environment variable is not set"

**Cause**: In secure mode, `KEYSTORE_PASSWORD` is not provided at runtime

**Fix**: Supply via environment variable or Docker secrets:
```bash
docker run -e KEYSTORE_PASSWORD="your-password" ...
```

### Container exits with "KAFKA_ADVERTISED_LISTENERS environment variable is not set"

**Cause**: `KAFKA_ADVERTISED_LISTENERS` was not provided at runtime

**Fix**: Set the variable based on your deployment:
```bash
docker run -e KAFKA_ADVERTISED_LISTENERS="PLAINTEXT://kafka:9092" ...
```

### JMX connection fails despite secure files being mounted

**Cause**: Missing `/etc/secrets/jmxremote.access` file or incorrect permissions

**Fix**:
1. Verify the file exists: `ls -la /etc/secrets/jmxremote.access`
2. Check permissions are 600: `chmod 600 /etc/secrets/jmxremote.access`
3. If using Kubernetes, ensure the secret mount mode is `defaultMode: 0600`

## Additional Configuration Variables

All standard Kafka broker configuration can be set via environment variables following the `KAFKA_*` pattern:

- `KAFKA_LOG_RETENTION_HOURS` (default: 168)
- `KAFKA_NUM_NETWORK_THREADS` (default: 8)
- `KAFKA_NUM_IO_THREADS` (default: 8)
- `KAFKA_SOCKET_SEND_BUFFER_BYTES` (default: 102400)
- `KAFKA_REPLICA_LAG_TIME_MAX_MS` (default: 30000)

See the Dockerfile for all available variables and defaults.
